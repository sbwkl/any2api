# 核心工程信念（any2api）

本文件定义设计知识库的 agent-first operating principles。它不是产品文案，而是约束文档与实现取舍的工程原则。

## 1. 仓库是系统记录

- 文档是事实源；聊天、issue、PR、commit 只做同步或证据。
- 当前事实只写当前状态；历史放变更索引或 `history/`。
- 状态以文档首部为准；没有证据不得标「已验证 / 已发布」。

## 2. 渐进披露

- `AGENTS.md` 是地图，`ARCHITECTURE.md` 是当前实现，`docs/product-specs/` 是产品行为事实源。
- 设计知识库用索引、状态与指针帮助 agent 按需读取，避免把全文塞进入口文件。
- 历史文档不得冒充当前 AC。

## 3. 机械约束优于口头规范

- 目录集合、文档状态、链接有效性用检查钉住，而不是靠记忆。
- 提交前静态检查 / 测试必须零错误、零警告；告警先修复，不跳过规则。
- 新增文档用语义化路径；历史编号冻结，不维护「下一批 ID」。

## 4. 证据与隐私

- 不臆造指标、证据、用户反馈或运行结果；没有数据写「待验证 / 待补」。
- 不把密钥、正文、本机敏感数据或第三方资料复制进知识库。
- 研究归档与生成物保留原位，知识库只放索引与指针。

## 5. 当前事实与设计理由分离

- 产品规格写「系统现在做什么」，设计知识库写「为什么这么做、哪些结论仍有效」。
- 部分失效的设计文档必须同时写 `superseded_by` 与当前事实源。
- 难回退决策进入 `adr/`；跨团队 / 不可逆 / 高不确定方案进入 `rfcs/`。
